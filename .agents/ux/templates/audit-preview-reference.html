Corporate Lease field with an empty display name is labelled 'New field'

Observed Defect & Evidence

In the Corporate Lease editor (read-only view), a saved custom field with an empty display name renders with the row button label "New field" (ref f10e1208). This sits directly above internal_lease_id, which correctly shows its own internal name.

EXPECTED BEHAVIOR
When a saved field has an empty display name, it falls back to displaying its internal schema identifier consistently.
OBSERVED ACTUAL
The saved field renders as "New field", giving the mistaken appearance of an unsaved draft or incomplete addition.
ux-evidence/live-corporate-lease-editor.png Click to expand ⤢
Design & Remediation Plan
Plain Language Solution:
When a saved field has no display name, show its internal identifier (e.g. field), matching the existing fallback behavior of the adjacent internal_lease_id row. Reserve the string "New field" strictly for fields in an unsaved draft state.

shadcn/ui Implementation:
No new components required. In the editor's field row, update the button label expression to use fallback display_name || name, which is already used inside arrayObjectPropertiesTable.tsx.

Fluent UI Guidance:
Fluent Labeling Principle: A label should always name the exact entity it describes; placeholder/state tokens must never substitute for persistent content.

No visible confirmation after 'Save changes' in editor; save bar quietly vanishes

Observed Defect & Evidence
Across Passwords and Contacts save journeys (explore/14, explore/20, explore/31, explore/36), clicking "Save changes" successfully triggers the PATCH request and closes the bottom unsaved changes bar. However, the app renders 0 confirmation toast notifications and leaves the status region completely blank.

Live DOM Audit: 0 toast containers ([data-sonner-toast] or .Toastify__toast).
Severity Calibration: BP-108 normally flags missing save confirmation as S2; kept at S3 because the bar dismisses and toggle state stays persisted.
Design & Remediation Plan
Plain Language Solution:
Provide positive visual feedback confirming the successful commit. Show a subtle, transient notification near the top-right or save location for 3 to 5 seconds, ensuring accessibility screen reader announcement.

shadcn/ui Implementation:
Trigger a Sonner toast (toast.success("Asset type settings saved")) via the application's existing toaster provider, or mount an inline text-xs notification beside the save bar with role="status" aria-live="polite".

Fluent UI Guidance:
Fluent Feedback Design (Sec 2.6): Operations with side-effects or persistent state updates require a transient success feedback notification.
