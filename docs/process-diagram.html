Process after a UAT deploy

A deploy webhook clears the harness gates and preflight signs in. After that, two phases run in order: ticket-free regression, then the feature run OpenCode coordinates.

1 · Deployment webhook

:8787

UAT deploy calls the harness

FastAPI on 127.0.0.1:8787. Docker Compose publishes that port on this machine. The worker takes one run at a time.

  • POST /trigger/uat-deploy with pr, ticket, or sha
  • A sha that is already accepted returns skipped and does not enqueue another run
  • Accepted runs land in runs/<ticket>/<run-id>/

Same queue, other doors

These skip the deploy body and enter preflight directly.

  • POST /run/LEX-1234
  • POST /run/pr/123
  • npm run ticket -- LEX-1234

2 · Custom gates on the webhook

require_secret · DeployBody

All four pass before a run is created. A failure answers the webhook and never starts preflight.

Secret

x-harness-deploy-secret or Authorization: Bearer. Must match HARNESS_DEPLOY_SECRET. With LOCAL_MODE=true and no secret, local calls are open.

Payload

Body includes a pull request, a ticket, or a commit sha. An empty body is rejected.

Ticket shape

A ticket, when present, matches LEX- plus digits. The key is stored uppercase.

Sha once

If that sha already has an active run, the response is skipped with the existing runId.

3 · Preflight

node scripts/preflight.mjs

Deterministic. No model calls Linear, GitHub, or Stytch. Any failed check sets preflight.json ok: false and the run stops as HALTED. A sha with no ticket is resolved to the pull request on that commit, then to the LEX- key in the title, branch, or body.

Halt

Failed check, missing ticket on the sha, or a context error. Status halted, verdict HALTED, report.md written. OpenCode does not start.

What the pack is allowed to contain

  • That ticket, plus parent, children, and related issues
  • Pull requests that mention the key, and only the files in those diffs
  • appUrl — live UAT, default https://e2e-test.uat.lexful.net

Phase 1

Regression E2E, not tied to a ticket

node scripts/specs.mjs

Checked-in suites under e2e test cases/. Each folder is one suite: its own FEATURE.md, specs, and page objects. Auth is auth-helper.ts. Paths such as /docs/assets resolve against QA_ENV_URL. Nothing in a suite imports a page object from another folder. The spec runner signs in with the cached Stytch session, then runs playwright test --workers=1 --project=e2e.

then
Phase 2

Feature run · OpenCode harness

server/app/pipeline.py

One LEX ticket or the PR resolved in preflight. The FastAPI worker is the orchestrator. It writes prompt.md, starts the qa agent, and runs Playwright itself. Agents receive the run directory, the pack, and the cookie file path. Stytch, Linear, GitHub, and OpenRouter secrets are removed from the OpenCode and Playwright environments.

  2. Every criterion and every matrix row becomes a test
  3. Writes planned-specs.json and returns
3 · only after a failed suite
subagent · Haiku 5.5 · 20 steps

qa-healer

The server resumes the same session and asks qa to delegate here.

  1. Reads playwright/results.json and output.log
  2. Replays the failing step with playwright-cli
  3. Patches the named spec or POM, then returns

Coordinator check between explorer and author

qa reads FEATURE.md. Missing URL, API list, or action matrix sends qa-explorer once more. Still missing, the coordinator stops and the server records HALTED because no spec file appeared.

Playwright, then at most three heals

Server runs npx playwright test --workers=1 --project=e2e on test_files. Exit 0 with at least one pass ends the run. Otherwise qa resumes, delegates only to qa-healer, and the server runs the same specs again. Cap is QA_HEAL_ATTEMPTS (3).
