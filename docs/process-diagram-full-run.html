1 · Trigger

:8787

Something starts the harness

The worker takes one run at a time. When both are queued, E2E User Journey TCs go first and the ticket waits.

  • A UAT deploy webhook, or a ticket or pull request
  • A sha that is already running is skipped
  • Each attempt gets its own folder under runs/

Two kinds of run

  • E2E User Journey TCs — the checked-in store, no ticket
  • Feature Specific TCs — one Linear ticket or its pull request

2 · Gates, then sign-in

preflight

A deploy must pass the gates before a run exists. Sign-in is deterministic. A failed check stops the run as HALTED and no agent starts.

Secret

The deploy call carries the harness secret, unless local mode is open.

Payload

A pull request, a ticket, or a commit sha. An empty body is rejected.

Ticket

When a ticket is present it is a LEX- key.

Session

Stytch session for UAT. A ticket run also loads Linear and the pull request.

Halt

Failed gate or failed sign-in. The run records HALTED and stops. OpenCode does not start.

What a ticket run is allowed to see

  • That ticket, plus parent, children, and related issues
  • Pull requests that mention the key, and the files in those diffs
  • Live UAT. No local app is started

E2E User Journey TCs

Checked-in journeys, then the healer

runs/phase-1/

The server runs the E2E store on live UAT. There is no ticket, no explorer, and no new tests. Only the healer is called, and only after a failure. A locator fix is written back into the store. A product bug is recorded on the run and the test is left as it is.

Healer loop
Server runs the E2E store Playwright, one worker, the checked-in specs
pass ends the phase · fail enters the loop

qa-healer, only

Spec drift — a renamed locator, a locator that matches too much, or a wait that expired while the control was already there — is patched in the E2E store. A wrong product outcome is reported. The healer does not add a test and does not hide a bug.

A few tries

The server runs the same suite again after a patch. The loop stops when the suite is green or the heal cap is reached. Then a waiting ticket may start.

Clean suite · phase ends Drift patched in the E2E store Product bug kept in bugs.md Result stays in runs/phase-1/

Feature Specific TCs

One ticket · explore, author, heal

runs/tickets/

The server coordinates. It does not let the agents run the suite. New cases cover behavior the E2E store does not already assert. Those specs stay in the feature-specific store for this run.

1 · every ticket
qa-explorer

Explore

Walks live UAT and writes what the ticket actually does.

  1. Notes the page, the calls, and the actions
  2. Marks behavior the E2E store already covers
  3. Plans a case only for what is still uncovered
2 · after the map
qa-author

Author

Writes specs for the new rows. Stays off the browser.

  1. Specs land in this run’s feature store
  2. Does not copy a case the E2E store already has
  3. Hands the file list back to the server
3 · only after a failure
qa-healer

Heal

Same idea as the journey loop, on this run’s specs only.

  1. Patches a drifted locator in the feature store
  2. Leaves a product bug unedited
  3. The server re-runs, a few times at most

Between explore and author

The coordinator checks that the map is usable. If it is still empty after one more look, the run halts and no suite starts.

After the functional result

A UI review can follow when that switch is on. It does not write tests and it does not change either store.

5 · Curate into the E2E store

after every feature run

Feature Specific TCs stay in the run. They do not enter the E2E store by themselves. A curator agent can do that pass once the ticket run has a verdict. The stores on the right are the two sides of that pass.

Read the feature store

Take the cases this ticket just added. Ignore anything the E2E store already runs.

Keep the relevant ones

Keep a case that belongs in an ongoing user journey. Leave a one-off check for this ticket where it is.

Add them to the E2E store

The next E2E User Journey run executes them. The healer keeps their locators current after that.

Most relevant cases only

Reads the feature-specific store. Drops cases the E2E store already covers and cases that only matter for this ticket. Adds the rest to the E2E store so the next journey run includes them.
